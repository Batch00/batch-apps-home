# CLAUDE.md

## Project
batch-apps.com home page: personal brand and app showcase portfolio.

## Tech Stack
- React + Vite (no router, single-page scroll)
- Tailwind CSS 3 (utility-first styling)
- lucide-react for all icons
- Deployed on Vercel; domain batch-apps.com (GoDaddy DNS)

## Hard Rules
- Icons: lucide-react only. No other icon libraries.
- Styling: Tailwind only. No external component libraries.
- App card data lives in `src/data/apps.js` - add new apps there only.
- Backend is Vercel serverless functions in `api/` only (shared helpers in `api/_lib/`). No other server.
  - `api/request-access.js`, `approve-request.js`, `deny-request.js`: access requests (Resend email, Supabase admin invite). Approve and Deny links expire after 14 days and are signed per action (`api/_lib/access-token.js`). Opening a link only shows a confirmation page; only its button's POST acts (`api/_lib/access-route.js`). `npm run test:access` (node:test) covers both.
  - `api/ytd.js`: `GET /api/ytd?year=YYYY`, read-only from BatchBrain's `brain.public_ytd` as `site_reader` via `YTD_DATABASE_URL`. Every payload passes the allowlist in `api/_lib/ytd-payload.js`.
  - `api/wrap-private.js`: `GET /api/wrap-private?year=YYYY`, owner only. Needs `Authorization: Bearer <Supabase access token>` (never a token in the URL), checked server-side with Supabase `auth.getUser` (`api/_lib/owner-auth.js`) against `OWNER_USER_ID`: 401 without a valid token, 403 for anyone else. Reads `brain.private_wrap` as `wrap_owner_reader` via `WRAP_PRIVATE_DATABASE_URL`; every response is `private, no-store`, and logs carry error codes only. The private block passes its own allowlist (`api/_lib/wrap-private-payload.js`). Rules and tests: `api/_lib/wrap-private-route.js`.
- Auth: Supabase is used for the invite password-setup overlay in `App.jsx` and the owner sign-in on `/<year>` (`src/wrap/owner/`). Supabase loads lazily in both; public wrap visitors without a stored session never download it.
- Public data rule: no dollar amounts, trip names, notes, journal text, or dates finer than a month may reach a public payload or page.
- Never use the Supabase service role key for YTD data; `YTD_DATABASE_URL` connects as `site_reader`, which can read `brain.public_ytd` only.
- The repo is public: never commit real private data (money, trip names or dates, routines). Tests and local dev use the synthetic `src/wrap/fixtures/private/sample.json` (fake names and numbers), never a response from the live private endpoint.

## YTD section
- `src/components/YtdSection.jsx` sits between Apps and About as the wrap's trailer: a bento of workouts (stats beside the total, a weekly chart with month initials and a hover or tap tooltip), film and TV (top 5 posters and counts), travel (counts over a lifetime dot map, "new this year" chips) and the BatchWrap tile (one primary button for the current year, then every earlier year from 2025 as a row of small "Past years" chips, so the tile keeps its height as years are added). Hidden on any error. In each desktop row the week strip or the map absorbs extra height, so no tile has dead space.
- The dot map (`src/components/ytd/DotMap.jsx`) draws `src/lib/dotMap.js`, a 2.5 degree grid generated by `node scripts/build-dot-map.mjs` from the atlases; the grid loads only when the tile nears the screen. The home page never loads d3-geo or the atlases. Which dots light is decided in `src/components/ytd/dotGrid.js` and tested in `dotGrid.test.js`.
- Region keys: US states are always `US-XX`, never a bare USPS code (CA, MN, LA, GA, AL, AZ and TN are also country codes). A country lights only its home territory (`src/wrap/globe/visited.js`, shared by the globe and the dot map generator): parts over 2,500 km from the main landmass, plus named territories in `NOT_HOME` (Svalbard for Norway), stay dark, so French Guiana and Svalbard never light. Regions too small to own a grid cell get a pin at a point inside them.
- `src/lib/regions.js` names payload codes (countries via `Intl.DisplayNames`, US states from a table) and orders this year's new places; both the home section and the wrap use it.
- `src/wrap/fixtures/2026.json` and `2025.json` are real payloads. `npm run dev` has no `/api`, so the home section and the wrap fall back to the matching year's fixture in development only.

## BatchWrap page (/2026)
- `main.jsx` checks the path (no router): `/<year>` for 2025 through the current year renders `src/WrapRoute.jsx`, which lazy-loads `src/wrap/WrapApp.jsx`. The home page must never import from `src/wrap/` (check `dist/` after a build).
- Vercel serves `wrap.html` for `/<year>` (`vercel.json`): the same app as `index.html`, with the wrap's title and share-preview tags (`public/og-wrap.png`, 1200x630). Both are Vite inputs in `vite.config.js`.
- A finished year (`is_partial` false) speaks in the past tense and hides chapters its data cannot fill. Every year's closing links to all the other years' wraps (2025 through the current year).
- `src/wrap/` has its own Tailwind build: `src/wrap/wrap.css` loads `tailwind.wrap.config.js` (type scale `text-mega`, `display`, `headline`, `title`, `lede`, `eyebrow`, `caption`), and the home config excludes `src/wrap/**`.
- Chapters live in `src/wrap/chapters/` and are listed in order in `chapters/index.js` (`length` in screens, `isEligible`). Build them from `Chapter`, `Frame`, `Beats` (`components/Chapter.jsx`) and the motion primitives `Reveal`, `Scrub`, `Grow`, `CountUp` (`components/motion.jsx`).
- Scroll triggers, time animates: `Reveal`, `Grow` and `CountUp` fire when progress crosses `at`, then run to completion on a timer, so a paused page always shows true values and only one beat is visible at a time. `Scrub` follows the scroll exactly and is for decorative motion only, never data.
- Travel globe: `components/Globe.jsx` lazy-loads `globe/renderer.js` (d3-geo orthographic on a 2D canvas, world-atlas 110m and us-atlas states) as its own chunk. `globe/route.js` holds the arc schedule and camera keyframes shared with the chapter text; `globe/codes.js` maps payload codes (ISO alpha-2, USPS) to atlas ids. The camera follows scroll; arcs are triggered and finish on a timer.
- Narrative lines come from `src/wrap/insights.js`: each rule has a chapter, an eligibility check and a line, and `CHAPTER_GATES` there decides when a chapter is too thin to show. Add or change copy there, never inline in a chapter. `npm test` (vitest) pins every line against the fixture.
- Film posters: `components/Poster.jsx` loads `https://image.tmdb.org/t/p/w342` plus the payload's `poster_path` (the allowlist only passes a bare TMDB image path), lazily, with a plain title card when it is null or fails. Closing carries the TMDB attribution; keep it while posters show.
- Each chapter has its own visual rhythm (opening count-up and ledger, travel sentence and chips over the globe, fitness bars and week strip, film poster wall and spotlight, patterns grid and numbered list). Keep one big count-up, in the opening.
- Beat navigation (`engine/useBeatNavigation.js`): tap or click the right half for the next beat and the left half for the previous; Right arrow and Space forward, Left arrow and Shift+Space back. Each chapter lists its beat positions in `chapters/index.js` (`stops`); keep them in step with the chapter's Reveal at/out values. Moves are smooth scrolls (instant under reduced motion). Only real interactive elements keep a tap (a, button, input, select, textarea, [role=button], [tabindex]); images, posters, cards and text all navigate.
- One scroll engine (`engine/scrollEngine.js`) writes `--p` and `--e` on each chapter. For canvas or JS motion use `useChapterProgress` (`engine/progress.js`). Reduced motion pins progress to 1 and flattens the page; `?motion=reduce` forces it, and `?state=final` previews the frozen-year copy in development.

## Private view (owner only, /<year>)
- A discreet "Owner sign in" (lock in the top bar, a link in the closing chapter) opens an email and password dialog. A non-owner account is told so and signed out. A stored session is checked on load; the page waits up to 4 s for it so the owner's story does not rebuild under them.
- Signed in as the owner: a "Private view" badge, a one-tap "Public view" toggle (remembered per device in localStorage, `batchwrap:view`) and sign out. The private block stays in memory only.
- Private chapters (`private: true` in `chapters/index.js`, gated in `CHAPTER_GATES` on `data.private`): Trips (names, dates, trip spend, spend per day, trip spend as a share of budget spend, never added to it), Training (strength by routine, stretching), Money (spend vs plan by month, top categories with percent of plan, savings rate, net worth trend) and Timeline (events by month and app). Their lines are `PRIVATE_RULES` in `insights.js`, tested in `insights.private.test.js` on the sample.
- The public view must stay exactly the public story: `src/wrap/privacy.test.js` pins the public chapter list, the fixtures, the share pages and home code, and `npm run check:privacy` builds and scans `dist/` (no sample, no private names in the home bundle or share pages).
- Development: `?private=sample` shows the private view on the synthetic sample without signing in (dev builds only).
